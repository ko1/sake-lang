Sake の Rust バックエンド: マイクロベンチマーク

2026-10-10 (JST) · sp4（16 コア、専用）· Ruby 4.0.6 +YJIT · rustc 1.93.1 · experiments/2026-10-10-rust-backend

bin/sabic（錆 + c）は Sake のプログラムを Rust に変換してネイティブにする。loops / fib / levenshtein の 3 本で、生成コードは Ruby 4.0 (YJIT) の 3〜21 倍、JIT なしの Ruby の 8〜53 倍速く、手書き Rust の 0.9〜1.6 倍以内。mixin のディスパッチ（Shape.area(s)）は 1 回 0.25 ns で、Rust の dyn Trait（1.03 ns）より速く、手書きの enum（0.19 ns）とほぼ同じ。

方法

  • 変換: 検査済みの SakeAST を入力に、関数を引数の型ごとに単相化して Rust を出し、rustc -O -C overflow-checks=on で実行ファイルにする。Integer は i64（溢れたらエラー）、nil は Option、Array とオブジェクトは Rc<UnsafeCell<…>>（Sake の値は参照なので共有する）、合併型は enum、mixin 呼び出しは match、yield だけのブロックは &mut impl FnMut、Array.each などのブロックはループに展開。対象外は行番号付きで断る。
  • 比較: Ruby（--yjit と --disable-yjit）、Sake インタプリタ、Sake → Rust、手書き Rust。同じアルゴリズムを同じ形で書き、出力の一致を確かめた。各 3 回の中央値（インタプリタは 1 回）、壁時計。
  • 入力: loops は 10,000 × 100,000 回、fib は 38（インタプリタは 32）、levenshtein は 40 文字 × 100 語の全組、shapes は 1,000 個 × 1,000,000 round（インタプリタは 10,000 round）。

  • インタプリタは Ruby(YJIT) の 150〜760 倍遅い。 AST を歩く Ruby のインタプリタで、1 操作ごとに型タグを検査している。
  • fib の差が 2.7 倍にとどまるのは Ruby 4.0 の YJIT が速いから。 約 1.3 億回の再帰呼び出しを 0.5 秒。基本ブロック内では一度 guard した型を使い回し、残る費用はメソッド呼び出しのフレームと戻り値の guard。
  • 手書き Rust との差（loops 9%、levenshtein 1.6 倍）は Ruby の意味論を保つ検査の分: Array.fetch の負の添字の正規化と範囲検査、a[i] = v の「末尾なら push」の分岐。床除算は原因ではない（手書きを床除算にしても 1.161 秒、切り捨てで 1.162 秒）。

結果: mixin ディスパッチ（shapes、109 回、秒）

Circle・Rect・Tri を 1,000 個混ぜた Array をなめて Shape.area(s) を足す。対照の shapes_mono は全部 Circle（呼び出し先が静的に決まる）。109 回なので「増分の秒数 = 1 回あたりの ns」。

  • Sake の mixin ディスパッチは enum の match になる。 include している型の集合が静的に閉じているので、vtable は要らず、本体（3 * r * r）が呼び出し側に展開される。Rust の dyn Trait は呼び出し先が決まらないので展開できず、約 4 倍の費用。
  • ただし生成コードには別の 1.2 ns/反復がある。 単相の shapes_mono でも 1.65 対 0.41。Array.each の要素取り出しとディスパッチの引数で Rc を clone しており、参照カウントの増減が 1 反復に 2 組。Sake の参照の意味論を Rc で写した代償で、引数を借用で渡す最適化で消せる見込み（未実施）。

限界

  • 対象は部分集合。Hash・Set・Regexp・rescue・(A|B).f・Thread・Tuple/Record のパターンは未対応で、sakelib の移植のような普通のプログラムはまだ通らない。
  • 型推論は typer とは別に生成器の中に書いた小さなもの。typer が式ごとの型を保持するようになれば置き換える。
  • Integer は 64 ビット。Rc は循環を回収しない。
  • マイクロベンチマーク 4 本だけ。文字列処理や Hash の多いプログラムでは別の結果になる。
