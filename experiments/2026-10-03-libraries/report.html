Sake でライブラリを 8 つ書いてみた

性格の違うライブラリを Sake で書き、使う側のプログラムも書いて、つまずきを 1 件ずつ記録した。どれも推奨の検査レベル（level 2）できれいに動くところまで書けた。一番の壁は、同じ型を違う要素型で使う「汎用コンテナ」が union にぼやけること。次が 1 ファイルしか書けないこと。推論器の不具合も 8 種見つかった。

3 · 共通して出た話題

何が重かったか

汎用コンテナが union にぼやける

collections · graph · validate · linalg · csvtable

フィールドの型は型ごとにプログラム全体で 1 つなので、同じ Heap を Integer と String で使うと、どちらの Heap も Integer | String になる。誤報の最大の原因だった。回避策は 3 つ出た。Record を使う（形ごとに型が分かれる）。要素型ごとに小さな型を作り、include HeapOps でコードを共有する（宣言は型 1 つにつき 3〜7 行）。比較しないように作り変える。

コールバックの代わり

events · webapp

処理する側を型にして、mixin のモジュールで振り分ける形（Java のリスナーに近い）か、Symbol と case/in の表で書けた。ただ、推論器はどの購読者がどのイベントを受けるかを知らないので、全購読者が全イベントを受けるとして検査する。Symbol の表と case がずれても気づけない。

1 ファイルのプログラム

ほぼ全員

ライブラリとクライアントを連結するので、エラーの行番号が数百行ずれる。呼ばれないライブラリ関数は検査されない（クライアントがテストの代わりになる）。使われない mixin が「no type includes M」と報告される。

推論器と処理系の不具合

再現ファイル付き
  • 型の表示が爆発する（誤報 9 件で 35MB、1 行 8.6MB）
  • case の in で網羅していても、else の型が残る
  • in true / in false を網羅と見なさず、else に true|false が残る
  • while (x = …) で x を狭めない（3 体が報告）
  • 常に raise する関数の呼び出しを、狭めのための出口と見なさない
  • 必須の関数を修飾なしで呼ぶと検査されない／仮置きの関数がブロックを取れない
  • --types が rescue されない raise を error と数える
  • Integer.chr(227) が BINARY の文字列になり、UTF-8 と連結すると Ruby の例外で落ちる

足りないもの、遅いもの

csvtable · json · webapp · linalg

Math::PI、<<、ブロック付きの gsub、pack、失敗時に nil を返す数値変換、UTF-8 の Integer.chr が足りない。228KB の JSON の解析に 12〜15 秒かかり、webapp では 1 リクエスト約 440ms のうち 40% が実行前の検査だった（共有マシンでの目安）。

4 · うまくいったこと

Sake が効いた場面

  • 実行前に見つかった本物の誤り（10 件）。ガード名のつづり誤り :payd。遷移表の列の取り違え。String[] の行への数値の書き込み。Struct を generate に渡す。エスケープしていない String をページとして返す（SafeHtml 型を作って、XSS を型だけで防いだ）。
  • 最初の実行で --strict を通ったもの。300 行の JSON パーサと生成器、Gram–Schmidt、LRU の連結リスト、規則をデータとして持つ検証器。
  • 演算子と数値の汎用性。同じ det / solve が、Rational では厳密に（Hilbert 行列の det = 1/6048000）、Float では近似で動いた。
  • 注釈なしの推論。--types が JSON の再帰的な型や、グラフの頂点の型（Hash[Task => …]）を正しく出した。
  • reader: を基本にする書き方。「邪魔にならなかった」「癖で accessor にしたが、全部 reader にしても全プログラムが動いた」（linalg・validate・json・events）。
5 · 次の手

直すものと、決めること

  • 直す3 節の不具合 8 種。どれも再現ファイルがある。
  • 決める汎用コンテナ。フィールドの型を「型ごと」ではなく、生成箇所（C.new を書いた場所）ごとに持つか。Array が生成箇所ごとに要素型を持つのと揃うが、局所解析で測った「フィールドは定義ごとに推論できる」とは別の方向になる。
  • 決める複数ファイル。require を入れるか、行番号の対応だけ持つか。呼ばれない関数を検査する方法（ライブラリ用の検査）も要る。
  • 決めるHash と Set の要素型の書き方。型の混ざった要素型 (String|Integer)[]。値の定数（Math::PI）。
  • 進行中ソケットとスレッドは別ブランチ io で動いている。webapp を、Sake 自身がサーバになる形でも作って比べる。
