# typer を双方向（署名ベース）で書き直す前の見積もり（2026-10-09）

問い: v0 の typer（前向きの抽象解釈、関数を実引数の型の組ごとに具体化）を、操作から引数への要求を先に集める双方向・署名ベースの
推論に書き直すと、本体を歩く回数はどれだけ減るか。書き直す前に、v0 の実体化（関数 × 引数の型）の表を使って見積もった。

## 方法

対象は P10 の SQL エンジン 2 本の段階 6（`experiments/2026-10-05-ai-writability/runs/p10-sake-{1,2}/stage-6/code`）。
検査器は commit `463a6174`（YJIT）。スクリプトは v0 の `Sake::Typer` を動かし、`@insts`（実体化の表）のキーを射影して数える。

- `inst_stats.rb MAIN`: 関数の数、実体化の数、関数あたりの分布、pass 数、typer の時間。
- `estimate.rb MAIN`: 本体を構文で走査し、「スカラー型を取る組み込みへの照合にしか使われない引数」（check-only）を見つける。
  その引数を具体化のキーから外したときの実体化の数。v0 の `run_body` の pass ごとの呼び出し回数も数える。
- `estimate2.rb MAIN`: 引数を 3 種に分ける。check（照合のみ）、flow（返す・格納・他関数へ渡す・容器に入れるだけ。型変数 α にできる）、
  look（本体が型を見る: 絞り込み、演算子、添字、フィールド、dispatch、表示）。check と flow をキーから外したときの実体化の数と、
  さらに容器の型を生成地点ではなく要素型（構造）で見たときの数。
- `estimate3.rb MAIN`: 引数ごとに「逃げるか」（返す・格納・渡す）「書かれるか」（容器への書き込み、呼び出し先での書き込みも推移的に）を見て、
  どちらでもない読み取り専用の引数だけを構造のキーにしたときの実体化の数。

走査は構文的な近似（ローカル変数への別名は `x = param` の形だけ追う）。実体化の射影は v0 の最終 pass の表に対して行い、
型は v0 の intern 表（`Typer::CANON`）から復元する。

## 結果

| | sake-1 | sake-2 |
|---|---|---|
| 関数 | 343 | 348 |
| v0 の実体化 | 4,481 | 1,864 |
| 実体化が 1 つの関数 | 185 | 163 |
| 最多の関数 | `Sorter.sort` 323 | `Sorter.merge_sort` 170 |
| pass 数 | 8 | 8 |
| `run_body` の呼び出し（pass ごと） | 831 1983 2196 1721 1049 803 49 | 895 952 804 728 629 553 252 |
| 引数 651 のうち check / flow / look | 18 / 48 / 585 | 16 / 91 / 544 |
| check を外す | 4,478 | 1,842 |
| check と flow を外す（α） | 4,441 | 1,507 |
| さらに容器を要素型で見る | 1,365 | 901 |
| 読み取り専用で逃げない引数だけ構造キー | 1,873 | 1,523 |

実体化の多い関数の中身（sake-1）: `Functions.call`・`substr`・`extreme` などは 284 の実体化が構造キーで 3 になる（行の配列が生成地点ごとに別の型だった）。
`Sorter.sort`（323、配列を返すので逃げる）と `Evaluator.evaluate`（302 → 187、要素の union が呼び出しごとに違う）は残る。

## 結論

- **双方向にしても本体を歩く回数はほとんど減らない。** 照合だけの引数は 5%、流すだけの引数を型変数にしても実体化は 1%（sake-1）〜19%（sake-2）しか減らない。
  引数の 9 割は本体が型を見る（絞り込み・演算子・添字・フィールド）ので、その型ごとに歩くしかない。これは推論の向きの問題ではない。
- **実体化を増やしているのは容器の型の表現**（生成地点ごとに別の型）。要素型で見れば 3.3 倍・2 倍減る。読み取り専用で逃げない引数に限っても
  2.4 倍・1.2 倍。ただし v0 が生成地点で型を分けているのは書き込み（push）を地点ごとに追うためで、要素型でまとめると別の呼び出し元の配列まで
  広がる。読み取り専用の引数に限れば安全。
- v0 の pass 1 回目の `run_body` は 831 で、2〜4 回目が 2 倍以上多い: 引数の型が広がるのを待って再評価する不動点の代金。

この見積もりの上で、書き直すかどうかは ko1 の判断に戻した。
