# Codex による価値の評価（2026-10-14）

ko1「sake language に価値はあるか…　ですね。レビューしてほしいもの」。バグ探しではなく、Sake という言語に価値があるか、誰にとってか、何が成り立てば意味を持つかを、別の系統のモデル（OpenAI Codex CLI 0.153.0）に独立に評価させる。

## 方法

- 依頼文: `prompt.md`（6 つの問い: 核のアイデア、対象者ごとの価値、評価実験の妥当性、本質と付随の切り分け、費用と危険、結論と次の手）。
- 対象: `commit.txt` のコミットを切り出した worktree（detached）。Codex はそこを読み、プログラムを走らせてよいが、書いてよいのは `./tmp-review/` だけ。
- 実行: `run.sh <worktree>`（`codex exec -s workspace-write`、利用上限の間は 15 分おきに再試行）。出力は `codex.log`（全経過、`codex.log.gz` に圧縮して保存）、`report.md`（最終回答）、`status`（UTC 時刻）。
- `report.md` の参照先は、Codex が書いた worktree の絶対パスを、対象コミットの GitHub 上の行へのリンクに置き換えた（内容は変えていない）。`tmp-review/` は Codex が確認のために書いたプログラム。

## 結果

2026-10-14 JST 20:56 に開始し 21:08 に完了（1 回目で成功、`status`）。全文は `report.md`。

Codex は文書と実験記録を読み、さらに自分で走らせて確かめた: examples 59/59、小テスト 209/210（残り 1 件は sandbox が socket を禁止したため）、ライブラリ 7 組の strict=2 での Ruby との一致、`s.strip` の拒否と hint、sabic での fib。

**評決**: 一般目的の言語としては今は価値が薄い。研究成果としては明確な価値がある。

- **核のアイデア**: 新規性は「小さいが本物」。新しい型システムではなく、モジュール修飾呼び出しの強制と束縛注釈の禁止という未探索の組み合わせ。得るもの（呼び出し箇所で要求型と探索先が見える、宣言と実装がずれない）より、失うもの（型名が操作数に比例、API 境界の契約がない、全体解析が要る、表現力を削る）が大きい。「一行で何が走るか分かる」は、演算子・mixin・union・裸の呼び出しでは成り立たないので言い過ぎ。
- **対象者ごと**: AI の生成は現状マイナス。AI のコードを人がレビューするのは仮説として有望だが未証明。人が手で書くのは大半でマイナス。ネイティブ化は限定的にプラスだが、効いているのは閉じた世界などの意味論の制限で、操作に型を書く記法ではない。研究としては強くプラス。
- **評価実験**: 誠実だと評価。ただし「操作に型を書くほうが変数に書くより良いか」には答えていない（構文・生態系・事前学習量が同時に違う、系列数が少なく天井効果がある）。答えるには、同じ処理系の上で注釈の位置だけ違う二つの人工方言を比べる実験（約 7,200 run）と、人間のレビュー実験（48–60 名、1–2 人月）が要る。静的に証明できた検査の 45% が全体解析に頼る（local-analysis）ことは、「操作に型があるから推論が局所的」という説明への強い反証だとしている。
- **本質と付随**: 本質は `T.op(x)` の強制、値メソッドの禁止、束縛注釈の禁止、閉じた呼び出し先。第一級ブロックなし、継承なし、値定数なし、`[]` が Tuple で `{}` が Record というのは付随的。価値のうち「呼び出し先を見せる」は TypeProf/RBS 上の LSP（inlay 表示）で、「閉じた世界の解析と AOT」は Ruby のプロファイルで、新しい言語なしに提供できる。Sake でしか確かめられないのは「束縛注釈を一切持たない」という設計そのもの。
- **勧告（順に）**: (1) 言語機能の拡張を止め、研究成果（否定的結果、500 本の推論、局所解析、LLM のコスト、AOT）を技術報告にまとめる。(2) 価値ある部分を Ruby のツールに移す。(3) 人間のレビュー実験を一度だけ行う。(4) AOT は「閉じた世界の Ruby 風部分集合」として別の主張で評価する。(5) Gem/Rails 互換の拡張は優先しない。
