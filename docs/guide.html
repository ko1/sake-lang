Sake-lang

the Sake language, pronounced /seɪk/

Sake is designed for the sake of finding a new place for types. It keeps Ruby's syntax, but you write the type on each operation, never on a variable. Each line then says exactly which function runs, and every name is checked before the program starts.

Ruby
name.upcase
3.times { p it }
pt.x
Sake
String.upcase(name)
Integer.times(3) { p it }
Point.x(pt)
  • Parsed by Prism
  • No types on variables, parameters, or fields
  • All names checked before running
  • Every operation checks its arguments

The language

The idea

Most languages put types where a value is bound (variables, parameters, fields), and each use has to look back at that declaration. Sake puts the type where the value is used.

Types on bindingsTypes on operations (Sake)
Examplex: String; x.upcaseString.upcase(x)
Meaning of a lineNeeds the declarationFixed by the line itself
A misspelled operationFound once the receiver's type is knownFound by name, before running
CostThe type is written onceThe type is written at every use; the uses check each other

The examples on this page are real. Each one is a file in docs/examples/, and the dark panel under it is that file's actual output.

Running a program

CommandWhat it does
bin/sake FILE.sakeChecks the whole program, then runs it
bin/sake -c FILE.sakeOnly checks; does not run
bin/sake --strict FILE.sakeChecks more before running (level 2, below)
bin/sake --types FILE.sakeExperimental: prints the inferred types without running

How strict

LevelHow to askAlso stops before running
0--strict=0only syntax, names, argument counts, calls on values, and the like
1(the default)type: a value whose type (other than nil) does not fit the operation; rescue: a rescue of an exception never raised
2--strictnil: a value that may be nil, used without a check; mixed: a type report where values of different types met in a field (a warning at level 1)
3--strict=3index-nil: the result of x[k], used without a check; exhaustive: a case whose literal branches may miss some value
4--strict=4unrescued: a raise that may reach the top level

Items can also be named: --strict=type,nil, or --strict=3,-index-nil. Whatever is not checked before running is still checked while running, by each operation.

A program can span several files and use Sake's library (Files, libraries, and arguments). To try Sake in a browser, with completion and the inferred types on hover, build the playground in ide/ (see its README).

The exit status is 0 on success, 1 for an error while running, and 2 for an error found before running (nothing ran).

Operations carry their type

Type.op(subject, args…) calls the operation op of Type. The subject comes first. A call on a value, such as name.upcase, is rejected, and the error shows how to write it with the type. Chains are rewritten as a whole.

Every type and operation name is checked before the program starts, so a typo never fails halfway through a run:

Nested calls read inside out. Two forms let them read in order, with every step still naming its type: x.T.f(…) is T.f(x, …), and _ is the value of the previous statement.

Rules

  • Built-in names follow Ruby's core library: Integer.to_s, String.include?, Array.each. Names from other languages, such as Integer.to_string, do not exist.
  • Calls on values are always rejected, including on literals such as 3.times and "a".upcase. For a literal, the hint names its type.
  • p.x suggests Point.x(p), p.x = v suggests p.Point.x = v, and x.nil? suggests x == nil.

Numbers and operators

Operators behave as in Ruby: a + b runs the + of a's type. For the built-in types, a fixed table gives the result for each pair of operand types.

A pair marked — is reported before running. There is no implicit conversion. Every operation also checks its arguments while running; with --strict=0, the same mistake stops when it runs:

Writing the operator with a type, as in Integer.+(a, b), runs Integer's + directly: the left operand must be an Integer, and the right one any type that + takes with it:

== compares any two values: by content for Tuples, Arrays, Hashes, Sets, Records and Structs, and false between different types. Tuples and Arrays are ordered element by element, so a Tuple makes a sort key of several parts. -x runs the -@ of x's type, and !x is x ? false : true:

Rules

  • - * / % ** take the same numeric pairs as + (Integer, Float, Rational, Complex). * also takes (String, Integer); Arrays have + - * as in Ruby.
  • < <= > >= compare two numbers, two Strings, two Symbols, or two Tuples or Arrays element by element.
  • == != compare any two values. A Struct type with Comparable and <=> is equal where <=> gives 0.
  • Integer / and % follow Ruby: -7 / 2 == -4. Dividing an Integer by zero raises ZeroDivisionError.
  • Integer ** negative raises ArgumentError; for a Rational, write 2r ** -1.
  • x += 1 means x = x + 1. && and || short-circuit as in Ruby.

Functions

Functions have no type annotations, and do not need them: what a function accepts follows from its operations (String.upcase(s) needs a String), and each call is checked with the types it is given. A function works with any type its operations accept, so square below works on both Integer and Float.

Optional and keyword parameters

As in Ruby, required parameters come first, then optional ones with a default, then keyword parameters, required (w:) or with a default. A default is evaluated at the call and may read the earlier parameters.

Every call's function is known before running, so keyword arguments are matched to their parameters by name then. A misspelled or missing keyword, or one given to a function that has none, is an error before running. There is no implicit Hash argument as in Ruby: write Hash[k: v] or a Record {k: v} for that.

Rules

  • The forms are def f(a, b) … end and def f(x) = expr.
  • Parameters: required, then optional (b = 1), then keywords (c:, d: 2), then a block parameter &b, which only passes the block on (Blocks). *rest collects the remaining positional arguments in an Array and **opts the other keywords in a Hash.
  • Arguments are evaluated in the order written. f(k:) passes the variable k.
  • first, *rest = xs and |a, *rest| collect the rest in an Array. *xs in arguments spreads only into built-ins that take any number of them: puts(*lines), format(fmt, *row), Array[*xs, 0].
  • return a, b and the literal [a, b] both make a Tuple. x, y = t takes it apart, and an Array too: missing elements are nil, extra ones dropped, as in Ruby.
  • Definitions are collected before anything runs, so a function may be called above its definition.
  • Recursion is limited to a depth of 10,000. Deeper calls raise SystemStackError.

Control flow

if/elsif/else, unless, while, until, the modifier forms, and c ? a : b all work as in Ruby.

Matching by type

x in Integer tests a value's type. case x with in branches picks the branch by type, literal, or Record shape. Inside a matching branch, the variable has the matching type, so a value that may be an Integer or a String can be used without a type report. There is no ===, so case/when is not supported.

x => Integer asserts a type, as in Ruby: after it, x is an Integer, and a value that does not match raises NoMatchingPatternError. Types are written on operations, never on variables or fields, so this is how a fact such as "a port is an Integer" is stated where the value is stored. It is also a check for nil.

The set of types is closed, so a case that may match nothing is found before running:

Rules

  • Only nil and false are falsy. 0 and "" are truthy.
  • An if without an else, and every loop, gives nil.
  • break and next work inside while and until.

Blocks

An operation that takes a block is called like any other, with the subject first. A block's single parameter can be named it or _1.

Your own functions receive a block through yield. If a block has several parameters and receives one Tuple, the Tuple is taken apart. return inside a block leaves the enclosing function.

Blocks are not values, so the interpreter knows which block each yield runs and checks block use before running:

break ends the call the block was given to, which then gives the break's value. A parameter can be taken apart, |(name, n), i|, and |head, *rest| collects the rest:

Optional blocks, and passing a block on

A function that checks block_given? may be called with or without a block. The checker knows for each call whether a block was given, so it follows only the branch taken. &b passes the function's own block on to another call; b is never a value.

Rules

  • A user function takes a block if and only if its body contains yield (or it takes &b). One that checks block_given? may also be called without a block; the checker then follows only the branch taken. A built-in operation either requires a block or rejects one.
  • def f(xs, &b) = Array.map(xs, &b) passes the function's block on. b can only be used as &b. Such a function may be called without a block, as in Ruby; passing none on to a call that needs one is an error.
  • A yield reached without a block is an error before running (level 1), and LocalJumpError when it runs.
  • A block with no parameters ignores its arguments. Otherwise, the number of arguments must match. A block with several parameters takes one Tuple or Array apart.
  • next v gives the block's value; break v the value of the call it was given to.
  • A block can read and assign the variables around it.
  • A block cannot be stored or returned: proc, lambda, and -> are not available.

Data

Types and instances

A class declares a type with fields; its values are instances. The fields are declared in the body with attr_reader, attr_accessor, and attr_writer, as in Ruby but with the names written bare. The type's operations are its own functions, called with the type's name, the instance first.

Declaring a type

In the bodyFields it declares
attr_reader x, yC.x(c) from anywhere; written only inside class C (with @x = v)
attr_accessor nC.n(c) and C.set_n(c, v) from anywhere
attr_writer wC.set_w(c, v) from anywhere; read only inside the class
attr_accessor n = 0 · items = Array[]a default: any expression, evaluated by each new that leaves the field out (like Ruby's def initialize(items = []), not once when the class is defined); trailing fields with defaults may be left out of new; it does not fix the field's type

Use attr_reader for every field that is not changed from outside, which is most of them: every write to a field is then in its own class, where the checker finds its type. C = Struct.new(:x, :y) is shorthand for a class C with attr_accessor x, y, and E = Exception.new(:line) for an exception type.

initialize

Types are never written on fields, so a fact such as "a port is an Integer" goes where every value passes: def initialize(c) runs after C.new has stored the fields, as in Ruby. It checks (@port => Integer) or converts (@celsius = Float(@celsius)). The checker runs it for each new call with that call's values, so a wrong argument is reported at the call.

Writing one class's definitions into another

class B < A is shorthand for writing A's definitions in B: A's fields come first, then B's own; A's functions become B's, with unqualified names and @x inside them meaning B's; B's own definition of a function wins. It is not inheritance: afterwards A and B are unrelated, and a B is not an A.

Instances

  • C.new(a, b) takes one positional argument per field, in the order the fields are declared.
  • Fields are mutable and instances are shared, not copied: after d = c, a change through d is seen through c. (Ruby's Data is immutable, which is why Sake's types follow Ruby's Struct.)
  • == compares the fields, unless the type defines == (or Comparable with <=>). Instances can be Hash keys and Set elements, except for a type with its own equality.
  • p shows #<struct Point x=4, y=6>, as Ruby does. A type's own to_s(c) is used by puts, "#{…}", Array.join, and %s; its own inspect(c) by p. Each returns a String.
  • x in Point and case x in Point test an instance's type.

Functions of a type

Functions written inside class C … end are C's operations: C.f(c, …). By convention the instance comes first. Inside them:

  • @x, @x = v, and @x += v read and write field x of the function's first argument. The type comes from the enclosing class, so @x is still an operation with a type (C.x(c)). There is no self.
  • Unqualified names, such as x (the reader) or another function of C, refer to C's operations first. A function named like a field replaces its reader, as in Ruby.
  • def C.f(c) outside the class is shorthand for def f(c) inside it. A class can be opened again to add functions.

Modules

A module is a namespace of functions with no type and no instances. It is used in two ways: as a home for plain functions, and as a mixin that types include.

class Cmodule M
Is a typeYes: C.new, fields, x in CNo
FunctionsC's operations, instance firstModule functions, or mixin functions for the types that include M
Called asC.f(c)M.f(x): directly (module_function), or dispatched to x's type
Combined byinclude M; class C < A writes A's definitions in Cinclude of other modules

Module functions

Functions after module_function are called directly: Geometry.dist2(…), Units.km(x). Such a module is a namespace, like Ruby's Math.

Mixins and dispatch

include M borrows M's functions into a class, as Ruby's modules do, but statically. Inside a borrowed function, unqualified names are looked up in the class that includes it, so Shape.describe uses the area of Square or of Disc. Calling a mixin function through its module, as Shape.describe(x), dispatches: it runs the function of x's type, which must include the module. This is the one place besides operators where the function is picked while running, and the module name on the call says so.

A module states what each includer must define with a function whose body is only raise NotImplementedError. A missing definition, a class that is not a type, and a direct call to a function that needs its includer are reported before running:

Operators for your own types

An operator belongs to a module: Arithmetic (+ - * / % **, unary - and +), Comparable (<=> and < <= > >=), Bitwise, and Indexable ([], []=). A type joins by including the module and defining the operator. With Comparable, <=> alone gives the comparisons, ==, and Array.sort.

Listing the types on the operation

When a value may be one of a few types that have an operation of the same name, list them on the operation: (A|B).f(x) runs the f of x's type. The list is checked before running:

Unqualified names

A call without a type, f(x), is resolved before running. It searches these places in order, and the first match wins:

  1. the enclosing class or module (and what it includes)
  2. top-level functions
  3. Kernel (puts, print, p, format, …)

The inner definition wins, so common names such as open stay usable. To reach an outer one, write its namespace, as in Kernel.puts(…).

Rules

  • The includer's own definition wins over a borrowed one. Modules included by a module are borrowed too.
  • include is not inheritance: M.f(x) always runs M's own f or dispatches to x's type. class B < A is not inheritance either: it only writes A's definitions in B.
  • Only modules can be included. A class without fields is an error: it is a type with nothing in it; write a module.

Tuples, Records, and arrays

A literal has no operation with a type, so its shape fixes its type when it is created. A growable collection is made by an operation with a type.

Written asIsElement types
[1, "a"]TupleFixed length and fixed positional types. Take it apart with x, y = t.
{x: 1, y: "a"}RecordThe set of fields and their types, for example {x: Integer, y: String}. Take it apart with r => {x:, y:}.
Array[1, "a"]ArrayNot declared. Any value can be added.
Float[], Point[p]Array of TT. Every write is checked.

A Record is read with a pattern. r => {mean:, count: n} binds mean and n. Field order does not matter, and a Record is never a Struct value, even when the fields match.

Indexing

x[k] runs the [] of x's type, and x[k] = v its []=. Array, Hash, String, Tuple, and MatchData have them.

  • A miss gives nil, as in Ruby, so with --strict you check a[i] before using it. Array.fetch raises an error instead.
  • A Tuple's length is part of its type, so reading outside it is an error.
  • Writing a Tuple position needs a value of that position's type.

Point[1, 2] means "an Array of Point". It is not Ruby's shorthand for Point.new(1, 2). When the mistake is visible in the source, it is reported before running:

Where a type is worth writing

A function needs no type: its operations say what it accepts. A Struct's field needs none either: its type comes from the values written to it, which T.new and T.set_x show. The one place a type pays is an Array that is filled later. Made with Array[], its element type is whatever gets pushed, so a wrong value is reported where the elements are used, far from where it went in:

Made with its element type, Integer[] (or Float[], Point[], Tuple[]), every push is checked where it happens. The type is written on the operation that makes the Array, not on a variable:

Rules

  • An Array of T checks each element on creation and on push, append, and concat. There is no conversion, so an Integer cannot go into Float[].
  • map, select, sort, and similar operations return an Array with no declared element type.
  • The contents of a Tuple or Record may be replaced by values of the same type. A Tuple is written with t[i] = v; a Record has no write syntax yet. The length is part of the type.

Strings and text

String and Regexp operations follow Ruby's, including the positions that a parser needs: String.index(s, t, start), Regexp.match(re, s, pos) (with \G anchored at pos), String.byteslice, and sub/gsub with a replacement String, a Hash, or a block.

Rules

  • There are no globals such as $1 or $~. Keep the MatchData: m = String.match(s, re), then m[1].
  • "#{x}", puts, and format("%s") use a type's own to_s.
  • Strings of incompatible encodings meeting (binary bytes next to UTF-8 text) raise EncodingError. Broken UTF-8 given to a regexp raises ArgumentError.
  • String.unpack, unpack1, and Array.pack read and write binary data with Ruby's formats.

Hash, Set, Range

Hash, Set, Symbol, and Range work as in Ruby. Their operations carry the type like everything else (Hash.each, Range.to_a), while h[k], 1..5, and :name are written as in Ruby.

  • Hash[k => v] and Hash.new(0) make a Hash, because {…} is a Record.
  • A missing key gives nil, or the default given to Hash.new.
  • A block over a Hash receives [key, value], which |k, v| takes apart.

Rules

  • Hash keys and Set elements compare as == does: numbers, Strings, Symbols, true, false, nil, Time, and Tuples, Records, Arrays, Hashes, Sets and Struct values made of these. A Struct type that defines its own == (or <=> with Comparable) cannot be a key. A Tuple or Record key is copied when stored.
  • Hash.new { … } is not available, because a block cannot be stored.
  • a[1..2] and s[1..3] slice an Array or a String.

nil

A value that may be absent is simply nil: its type is nil | T, with no Option wrapper. Check it with if x, while x, x != nil, or return unless x. When a nil reaches an operation that needs something else, the error tells you where it can come from.

By default (level 1), an unchecked nil is caught when it runs. --strict (level 2) reports every unchecked use before running. A local variable you have tested counts as checked. A field you read again does not, because fields are mutable.

Exceptions

raise, rescue, else, ensure, and retry work as in Ruby. An exception type is declared with Exception.new: it is a Struct type whose first field is message. There is no hierarchy, so a rescue lists the types it catches.

The checker tracks which exceptions each function may raise. By default it reports a rescue that can never match; level 4 also reports a raise that nothing rescues:

Rules

  • raise "msg" raises RuntimeError. raise T, "msg" works when T has only message; otherwise write raise T.new(…).
  • rescue => e catches everything rescuable; e is a union, so narrow it with case e in …. Exception.message(e) reads any exception's message.
  • SystemStackError, LocalJumpError, and NotImplementedError are program errors: they cannot be rescued. TypeError and NoMatchingPatternError (a failed x => T or case/in) can be, as in Ruby.

Values computed once

Sake has no value constants such as PI = 3.14: a constant would be a value with no operation naming its type. A function gives the value instead, def pi = 3.14159. When the value is costly to build, such as a table, once { … } computes it the first time its place in the program runs, and keeps it for the whole program:

Rules

  • Each once in the source is one value, shared by every call and every thread.
  • A once that needs its own value while computing it raises SystemStackError.

Programs

Files, libraries, and arguments

require "lib/web" reads lib/web.sake next to the requiring file, once. When there is no such file, it reads Sake's library, sakelib/. The argument is a string literal and require is a statement at the top of a file, so the files of a program are decided before running. A required file's top-level statements run first, and every message names its file.

sakelib/ holds ports of Ruby's standard library, each tested against Ruby's own output: json, csv, base64, digest, zlib, strscan, shellwords, uri, cgi, erb, optparse, logger, benchmark, date, matrix, prime, abbrev, and tsort. Their calls are Ruby's with the type in front: JSON.parse(s, symbolize_names: true), CSV.parse(text, headers: true), Digest::SHA256 as SHA256.hexdigest(s). Each library's notes (sakelib/notes/) list what differs from Ruby.

Rules

  • ARGV is the Array of the program's arguments (bin/sake prog.sake a b). It is written like Ruby's constant but is an operation: every use gives the same Array.
  • exit(status) ends the program (ensure clauses run); warn(msg) writes to stderr.
  • A require inside a function or a block, or with a computed name, is an error before running.

Input and output

puts, print, p, and gets work as in Ruby. To choose where text goes, take an IO value: IO.stdout, IO.stderr, IO.stdin, or a file from File.open. There are no globals such as $stdout; as with ARGV, the value comes from an operation. Files and streams are one type, IO, so one function writes to either.

Rules

  • File.open(path, mode = "r") gives an IO; with a block, it gives the block's value and closes the file after the block.
  • IO.puts, print, write, gets, read, readlines, each_line, eof?, flush, and close take the IO first. File.read, File.write, and File.readlines work on a path.
  • Reading or writing a closed IO raises IOError. Writing to IO.stderr flushes stdout first, so the two keep their order.

Threads and sockets

Thread.new { … } runs a block in a new thread. The block shares the variables around it, as every block does; Queue passes values between threads and Mutex.synchronize guards shared state. TCPServer and Socket give a server and a client, enough for a small web server written in Sake.

Rules

  • Thread.value(t) gives the block's value, and the checker knows its type. An error in a thread is raised again by Thread.value or Thread.join.
  • TCPServer.new(host, port), TCPServer.accept, Socket.connect(host, port), Socket.gets, read, write, and close; network errors raise IOError.

Seeing the types

--types runs a whole-program type inference without running the program. For every operation that checks its argument, it reports one of the following:

  • proven: the check always passes;
  • partial: the value's type is a union, so the check is still needed;
  • error: the check always fails;
  • unknown: the inference could not tell.

It also lists the element type of each Array and the type of each field. None of these types were written in the program. The playground (ide/) shows the same results in its Types tab and on hover.

What Sake rejects

Sake rejects anything that would hide which code runs, and anything not designed yet. All of it is reported together, before running:

Rules

  • Never allowed: self, @x outside a function of a Struct type, send, method_missing, define_method, the eval family, instance_variable_get/set, const_get/set, and subtypes: a value has exactly one type.
  • By design: there are no value constants, and no globals. Define a function instead (def pi = 3.14159), with once { … } for a value built once (Values computed once); ARGV and IO.stdout are operations.

Errors

Before running (exit status 2)

All errors are reported at once, in source order, and nothing runs.

FILE:LINE:COLUMN: error: MESSAGE
  hint: SUGGESTION

Errors found before running:

  • syntax errors;
  • unknown types, operations, and functions;
  • a wrong number of arguments, and an unknown, repeated, or missing keyword argument;
  • a require that is not a string literal at the top level, or a file that cannot be read;
  • a block given where none is taken, or missing where one is required;
  • calls on values;
  • forbidden or unsupported syntax;
  • duplicate definitions;
  • a literal of the wrong type in T[…];
  • by default (level 1), a value whose type does not fit the operation, such as "" + 1, and a yield reached without a block;
  • with --strict (level 2), a value that may be nil used without a check;
  • with --strict=3, the result of x[k] used without a check, and a case whose literal branches may miss a value.

Not yet supported

Each of these is rejected before running. Most are waiting on a design decision.

  • Writing to Record fields
  • The type scope Integer.(a + b)
  • case/when (use case/in), %w[], %i[]
  • for: not planned; iterate with an operation such as Range.each(1..3) { |i| … }
  • Patterns other than types, literals, alternatives, and Record shapes (array and find patterns, pins, guards, x => Integer => n)
  • Nested names such as URI::HTTP (only Math::PI, Float::INFINITY and the like are read)
  • Storing a block: proc, lambda, ->, and &b as a value. A prototype type-checks them at a linear cost, but blocks kept in one container are then checked with each other's argument types, which gives false reports; blocks stay second-class for now
