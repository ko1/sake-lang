# i18n (Ruby's i18n gem, Simple backend)

`require "i18n"` → `sakelib/i18n.sake` (requires `yaml` for `I18n.load_yaml` and `date` so `I18n.l` takes a Date).
Test: `test/sakelib/i18n.{sake,rb}` (identical output); the `.rb` twin uses the installed gem (i18n 1.15.2).

Shape: `I18n` is a module of module functions over one `I18n::Config` kept by `once` (locale, default locale,
fallbacks, enforcement, the translations Hash). `I18n.backend.store_translations` is `I18n.backend_store`;
setters are `I18n.set_locale(:ja)` & co.; the gem's nested exception classes and `I18n::Config` are nested in
`module I18n` as in the gem (since 2026-10-10; before that they were top-level: `MissingTranslationData`,
`I18nArgumentError`, `I18nConfig`, ...).

## できたこと / できなかったこと

- **Translations as data.** The store is `Hash[locale => Hash]`, values `String | Hash | Array | Integer | nil`
  (whatever the Hash literal or YAML gives). `lookup(l, keys)` walks the locale, then its fallbacks; a Hash
  value is pluralized when `count:` is given (`:zero` for 0 if present, `:one` for 1 — `1.0 == 1` as in Ruby —
  else `:other`, missing form → `InvalidPluralizationData` with the gem's text), a String is interpolated when
  any value was given (the gem's rule: `I18n.t(:hi)` keeps `%{name}`, `I18n.t(:hi, other: 1)` raises
  `MissingInterpolationArgument` with the gem's message, `{other: 1}` included). `default:` resolves Symbols
  as keys (with the same scope and count), Arrays in order, Strings with interpolation, anything else as is.
  `I18n.t("foo")` gives the subtree Hash with Symbol keys, as the gem.
- **Localize.** `I18n.l(t, format: :short)` reads `time.formats.short` (`date.formats` for a Date; a String
  format is used as is), replaces `%a %A %b %B %^a ... %p %P` from `date.day_names`, `abbr_month_names`,
  `time.am/pm`, then `Time.strftime` (`Date.strftime` of `sakelib/date.sake`). The gem ships no `en` data
  (rails-i18n does), so the test stores the Rails `en` formats and names on both sides; a missing format is
  the gem's `Translation missing: en.time.formats.nope`.
- **Enforcement and fallbacks.** `enforce_available_locales` (default true) checks `t`/`l`/`set_locale`
  against the stored locales, as the gem (an empty store makes even `:en` invalid, as in a bare Ruby script).
  Fallbacks are off until `set_fallbacks(Array[:en])` (the gem needs the `Fallbacks` module included); the
  missing-translation text still names the requested locale (`ja.zz`).
- **YAML**: `I18n.load_yaml(path)` takes a file whose top-level keys are locales and stores each; String keys
  become Symbols, `n: 7` stays an Integer.
- **Not ported**: the option flags of `t` (`raise:`, `throw:`, `deep_interpolation:`, `cascade:`, custom
  `exception_handler`) — Sake has no `throw`/`catch` and no stored handler block; `%<name>d` formats; other
  backends and pluralization rules (would be a stored block per locale); `I18n.load_path` laziness; a
  per-locale fallbacks map; `DateTime`.

## 書き心地

- **`**values` cannot be passed on.** Wrote `def translate(key, ..., **values) = t(key, ..., **values)` and the
  Array-of-keys branch `Array.map(key) { |k| t(k, ..., **values) }` → `error: `**` is not supported` at both
  call sites. A function may *collect* `**opts`, but a call may not spread a Hash into keywords. Rewrote the
  three public entry points (`t`, `translate`, `t!`) to collect once and call one internal
  `translate_with(key, locale, scope, default, count, separator, values, strict)` with the Hash as a plain
  argument. That internal function is in fact the clearer shape (every option positional, no defaults to
  repeat), and the gem's own code does the same (`options` Hash) — but a Ruby reader expects the alias to be
  one line.
- **Setters.** `I18n.locale = :ja` has no form on a module (and the strscan notes already found that
  `Type.pos=(x, v)` is not syntax), so `set_locale`, `set_default_locale`, `set_enforce_available_locales`,
  `set_fallbacks`, following the Struct writer convention `set_x`. `I18n.fallbacks = [:en]` and
  `I18n.fallbacks[:ja]` (a setter and an indexable object) became `set_fallbacks(Array[:en])` and
  `fallbacks(:ja)`; readable, but every setter is a renaming a Ruby user must look up.
- **An Array key is a different operation.** `format_for` called `t!(Array[type, :formats, format])` meaning the
  key path `time.formats.short`; in the gem (and here) an Array of keys means "translate each", so it looked up
  `en.formats` and raised at run time, in the test. The checker could not see it: both are legal `t!` calls
  with legal types. Built the key as `String.to_sym("#{type}.formats.#{format}")`, as the gem does. The
  lesson is the gem's, not Sake's: overloading one parameter by type (`key` as path or as list) is where a
  typed-on-operations language would want two names (`t` and `t_all`), and Sake let me keep the overload.
- **Module state.** `def config = once { I18n::Config.new(:en, :en, Array[], true, Hash[]) }` is the whole of the
  gem's `I18n.config`; every function calls `config` and reads or writes a field (`I18n::Config.set_locale(config,
  l)`). It is more words than `@@locale` but the state is one value in one place, and `with_locale`'s `ensure`
  restores it through the same writer.
- **Values of an open union.** A translation value is `String | Hash | Array | Integer | nil`; the operations on
  it are `(entry in Hash)`, `(entry in String) ? interpolate(...) : entry`, `case v in Hash ... in Array ...
  else v` in `symbolize`, and `raise ... unless v in Array` before `v[i]` in `name_at`. Each check is one `in`,
  and `--strict` accepted the whole file on the first run apart from the `**` errors above and the Array-key
  mistake it could not know about. `v = (v in Hash) ? v[k] : nil` as the lookup step reads as well as the
  gem's `result = result[key] if result.is_a?(Hash)`.
- **Hash keys from YAML.** `out[(k in String) ? String.to_sym(k) : k] = symbolize(x)`: a conditional in the index
  position, fine. The YAML library gives String keys and Sake's Hash literal gives Symbols, so the merge
  symbolizes everything; the gem has the same `deep_symbolize_keys`.
- **The twin's surprises were the gem's**: after `load_translations` the gem's cached `available_locales_set`
  still rejected `:de` (`I18n.config.clear_available_locales_set` in the `.rb`); the Sake side has no cache
  to clear. And `I18n.t("foo", locale: :ja)` with fallbacks gives `ja`'s subtree only, not a merge, in both.

## Built-ins requested

- Passing a collected `**opts` on to another call (`f(**opts)`): the one thing that forced a restructure; the
  callee is known, so the keywords could still be checked at the call.
- `Kernel.format` with `%<name>d` / `%{name}` from a Hash (Ruby's `format("%<n>d", n: 1)`): would give the gem's
  second interpolation syntax for free.
- `String.unicode_normalize` exists; a `String.each_char` with the codepoint would make `transliterate` a
  lookup per character without `gsub`'s block.
- A `Hash.dig(h, *keys)` with several keys (the built-in takes one): the lookup loop writes it by hand.
