# Brief: write an interpreter for a small language, in Ruby (AI writability, large-program pilot)

Other AI agents will later be asked to change, extend, debug and answer questions about this program,
in Ruby and in a Sake port of it. You write the Ruby original, the language specification, and the
tests. You are not a solver: do not leave notes about future tasks.

## The language: Mini

A small dynamically typed scripting language. Design it yourself, precisely, and write it down in
`SPEC.md` (the only description solvers get besides the code). It must have at least:

- values: integers (arbitrary size), strings, booleans, nil, arrays, maps (string or integer keys,
  insertion-ordered), functions (closures, recursion), built-in functions;
- `let` declarations and assignment (also to array elements and map entries), block scope;
- `if`/`elif`/`else`, `while`, `for x in <array or map keys>`, `break`, `continue`, `return`;
- operators with precedence and associativity: arithmetic (`+ - * / %`, with integer division
  rounding toward negative infinity), comparison, equality, `and`/`or`/`not` (short-circuit), string
  concatenation with `+`, unary minus; string interpolation `"a {expr} b"`;
- `throw <value>` and `try ... catch e ... end` (any value can be thrown; runtime errors are catchable
  as a map with `"kind"` and `"message"`);
- 15-25 built-in functions (`print`, `len`, `push`, `pop`, `keys`, `str`, `int`, `type`, `range`,
  `join`, `split`, `slice`, `sort`, `contains`, ...), each with its argument checks and error messages;
- a static pass before running that reports undefined names, `break`/`continue` outside a loop,
  `return` outside a function, and duplicate `let` in one scope, with line:column;
- exact error output: lexical, syntax, static and uncaught runtime errors print one line
  `<kind> error at <line>:<col>: <message>` to standard output and stop. Everything goes to standard
  output; the exit status is always 0.

The program reads a Mini program from standard input and runs it: `ruby large/mini/ruby/main.rb < prog.mini`.

## The code

`experiments/2026-10-05-ai-writability/large/mini/ruby/`: 10-14 files, 2,500-3,500 lines in total
(code, not padding), loaded with `require_relative` from `main.rb`: for example tokens, lexer, AST,
parser, static resolver, values, environment, interpreter, built-ins, errors, string formatting.
Write it as a careful maintainer would want to inherit it. Types of data must flow across files: a
token's position reaches error messages; an AST node type is made by the parser, checked by the
resolver and run by the interpreter; values are made in one place and used in many.

A Sake port will mirror your files and functions one to one, so stay inside the part of Ruby that has
a direct counterpart there (read `/home/ko1/app/sake/docs/tutorial.md` sections 7, 8, 9, 13 for what
Sake rejects), while writing natural modern Ruby:

- AST nodes and tokens as `Struct`/`Data` (or plain classes with `attr_*`), dispatched with `case/in`
  or `case/when` on their class; no inheritance among your own classes; no `method_missing`,
  `define_method`, `send`, `instance_variable_get`, `eval`, refinements, or monkey-patching of core
  classes; constants are fine (the port turns them into functions).
- Exceptions for Mini errors are your own exception classes.

## Tests

`large/mini/tests/NNN-<topic>.mini` and `.out` (expected standard output, generated by your
implementation and checked by you against SPEC.md): at least 200, covering every feature, every
built-in, every error kind and message, and edge cases (deep recursion up to 100 levels, empty
collections, shadowing, closures capturing loop variables, nested try/throw, interpolation edge
cases). Keep each test small and fast (it will also run under a much slower interpreter): under
2,000 evaluation steps, under 40 lines. Also write `large/mini/run_tests.rb IMPL` that runs every
test with `IMPL` (`ruby` or `sake`) and reports mismatches; for `sake` it runs
`/home/ko1/app/sake/bin/sake --strict=2 large/mini/sake/main.sake`.
