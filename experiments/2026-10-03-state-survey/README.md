# 状態の型づけのサーベイ（2026-10-03）

ko1「状態をどう持つかだよなー。何か、プログラミング言語理論にうまい手はないかサーベイして」への回答。Sake のフィールド（変更できる状態）の型を、注釈なしで、汎用の入れ物でもぼやけずに決める手を、先行研究から整理した。

- 解説ページ（artifact）: <https://claude.ai/artifact/S1JgLX5Ux9heEXGi6Q8u3J>（`report.html`）
- 方法: 記憶にある文献を系統に分けて整理し、書誌の怪しいもの（Agesen の CPA、Plevyak と Chien、Wang と Smith の DCPA、Crystal の型引数の推論）を Web 検索で確かめた。他の書誌は記憶に基づく（未検証）。
- 結論: 変わらないフィールドの型は値の型に含める（Tuple / Record と同じ扱い。宣言なしで ML の型引数の精度）。変わるフィールドは、生成箇所と 1 段の文脈で分ける（DCPA、オブジェクト感応。Sake の推論器は関数について既に CPA の形）。作った直後の初期化には recency abstraction。型引数の宣言（A）は型を宣言に書くことになるので採らない（初版の「getter の型が操作の側で決まり『型は操作に書く』と揃う」は誤りとして撤回。ko1 の指摘: Sake は型を書かない。getter の型が書かれていないのはユーザ関数と同じで、問題は推論の精度だけ）。
- 未検証の仮説: この組み合わせで、ライブラリ試作の汎用の入れ物に由来する誤報が消え、健全性を保ち、解析時間が実用の範囲に収まる。確かめ方は report.html の 4 節。
