# プログラムの構造と名前解決

## ファイルと `require`

プログラムは 1 つのファイルと、それが require するファイルです。トップレベルに書けるもの:

- **`require "path"`**: `path.sake`（拡張子は省略可）を、require するファイルのディレクトリからの相対で読みます。引数は**文字列リテラル**、`require` はファイルの**トップレベルの文**でなければなりません。プログラムを構成するファイルは実行前に決まります。各ファイルは、誰が require しても 1 回だけ読まれ、循環は既に読んだファイルで止まります。require されたファイルのトップレベルの文は、require したファイルの文より先に走ります（1 つのファイルの `require` はすべて先に読まれます）。すべてのファイルの定義はまとめて集められるので、ファイルをまたいで名前を任意の順で使えます。同じ名前を 2 つのファイルで定義するのはエラーです。メッセージは各行のファイルを名乗ります（`lib/units.sake:4`、`from lib/broken.sake:3`）。
  - `require "json"` のように兄弟に無い名前は、処理系に付属する [ライブラリ](10-library.md)（`sakelib/`）から探します。
- **関数定義**: `def name(params) ... end` と `def name(params) = expr`。
- **名前空間付きの関数定義**: `def Type.name(params) ...`。`class Type` の中で `name` を定義するのと同じです。
- **名前空間**: `class Name ... end` と `module Name ... end`。本体に書けるのは `def name(...)`（レシーバ無し）、`include Module`、class では `attr_reader`/`attr_accessor`/`attr_writer` の行です。
  - `class` は**型**（Struct 型）を宣言するか、型に（`String` のような組み込み型にも）操作を足します。
  - `module` は**型を持たない**名前空間です。型に `module` を使うのは静的エラーで、hint が付きます。
- **Struct 型**: `attr_*` の行を持つ `class Name`、または `Name = Struct.new(:field, ...)`。
- **文**: それ以外の式。文は順に実行されます。

すべての定義は実行前に集められるので、関数は定義より上の行から呼べます。

規則:

- 名前空間は入れ子にできません（`A::B` は拒否）。
- クラスは継承しません。どの class についても、`class B < A` は A の定義を B に書き写す略記で、その後 A と B は無関係な型です（[Struct 型](07-structs.md)の章。この本では、プログラムが `class` や `Struct.new` で定義する型をすべて Struct 型と呼びます）。
- `def self.x` は拒否されます。Sake に `self` は無いからです。
- 1 つの名前空間で同じ名前を 2 度定義するのはエラーです。組み込みの操作の再定義もエラーです。
- 定数に代入できるのは `Struct.new` だけです。Sake に**値の定数は無く**、名前付きの値は関数にして（`def pi = 3.14159`）呼びます（`pi`）。`PI = 3.14` は静的エラーで、hint がその関数を示します。`once { ... }` は 1 度だけ計算する値のための形です（[組み込み操作](09-builtins.md)）。

## 型付きの呼び出し

`Type.op(args...)` は名前空間 `Type` の操作 `op` を呼びます。慣習として、主語（subject）が第 1 引数です。`Type` と `op` の両方が存在しないとプログラムは実行前に拒否され、綴りの候補と、`op` を定義している他の名前空間が示されます。

## 連鎖と `_`

一連の操作を左から右・上から下に読める 2 つの形があります。どちらも各段が型を名乗ります。

- **連鎖。** `x.T.f(args...)` は `T.f(x, args...)` です。段 `.T` が型かモジュールを名乗り、その左の値が第 1 引数になります。段は続けて書け、次の行の先頭にドットを置くこともできます。操作の無い `x.T` は静的エラーです。

  ```ruby
  String.split(line, ",")
    .Array.map { |s| String.strip(s) }
    .Array.join("|")
  ```

- **`_`** は同じ本体（関数、ブロック、分岐、トップレベル）の直前の文の値です。本体の最初の文や定義の直後で `_` を読むのは静的エラーです。括弧の中と文字列の補間の中では、最初の文は外側の文の `_` を読みます。`_` は無視する名前としては使えますが（`|_, v|`、`a, _ = t`）、ローカル変数を名付けた `_` は読めません。

  ```ruby
  String.split(line, ",")
  Array.map(_) { |s| String.strip(s) }
  Array.join(_, "|")
  ```

## 値へのメソッド呼び出しは無い

小文字のレシーバを持つ呼び出し、`x.op(...)`、`"lit".op`、`3.times` は静的エラーです。エラーは型付きの形を提案し、1 段なら連鎖の形（`x.T.op(...)`）も提案します。

- **連鎖**は全体を書き直します: `s.strip.upcase` には `String.upcase(String.strip(s))`。
- **フィールドアクセス**にはリーダ: `p.x` には `Point.x(p)`（または `p.Point.x`）、`p.x = v` には `p.Point.x = v`（関数のセッタなら `Point.set_x(p, v)`）。
- **リテラルのレシーバ**は候補をそのリテラルの型に絞ります。
- **`x.nil?`** には `x == nil`。

## 型を付けない呼び出し

レシーバ無しの `f(args)` は静的に解決されます。最初に見つかったものが勝ちます。

1. 囲んでいる class か module（その組み込みの操作、Struct のアクセサ、include した関数を含む）
2. トップレベルの関数
3. `Kernel`（`puts`、`print`、`p`）

内側の定義は外側を**隠します**。同じ名前が複数の段にあるのはエラーではなく、外側の定義は常に名前空間付きで呼べます（`Kernel.puts`）。トップレベルのコードには囲む名前空間が無いので、解決は 2 から始まります。

## include

class か module の本体の `include M` は、module `M` の関数を借ります。Ruby の module を静的に解決したものです。

- **借用。** `M` の各関数 `f` は、include した名前空間 `X` の `X.f` になります。`X` が既に `f` を持つならそれが勝ちます。`M` が include した module も借ります。
- **順序。** Ruby の祖先順で探します。**最後**に include した module が先です。`include A` の後に `include B` なら、両方にある `bar` は B のものです。
- **include 側での解決。** 借りた関数の中の型無しの名前は `X` で解決されるので、`M` は `X` が提供する関数（`each` など）を使えます。実行時のディスパッチは無く、各 `X.f` は実行前に固定されます。`X` が Struct 型なら `@x` は `X` のフィールドです。
- **要件。** `M` の関数が必要とする名前を `X` が持たないと、`include M` は静的エラーです。そのような関数を `M.total(x)` と直接呼ぶのも静的エラーで、include した型を通して呼ぶ hint が付きます。
- **制限。** include できるのは module だけで、include の循環はエラーです。
- **継承ではない。** `include` は部分型関係を作りません。

## module の関数の呼び方: module_function とディスパッチ

型や module の 1 つの名前は 1 つの関数です。Sake には `def f` の隣の `def self.f` はありません。「インスタンス」の形は、値が先に来る（`T.f(x, ...)`）という意味しか持たないからです。Ruby でクラスメソッドとインスタンスメソッドが同名のとき（`Net::HTTP.get(uri)` と `http.get(path)`）は、片方に別の名前を付けるか、1 つの関数が第 1 引数の型で形を見分けます。

module の関数は Ruby と同じく 2 種類あります。

| 種類 | 宣言 | `M.f(args)` |
|---|---|---|
| module 関数 | `module_function` の後、`module_function :f`、または `def M.f` | `M` 自身の `f` が走る（静的） |
| mixin 関数 | それ以外の module の関数 | **ディスパッチ**: 第 1 引数の型の `f` が走る。その型は `M` を include していなければならない |

- **主語が無い。** mixin 関数は引数無しで呼べません（`M.foo`）。ディスパッチするものが無いからです。どの型も `M` を include していないときに呼ぶのも静的エラーで、`module_function` を使う hint が付きます。
- **型検査。** 第 1 引数が取りうる型のすべてが `M` を include することを型推論が検査し、していないものを `type` の問題として報告します。実行時は、include していない型は `TypeError` を投げます。
- **静的な呼び出し。** 型自身の名前空間は常に静的です。`Basket.total(b)` は Basket の `total`（自分で定義したものでも `Summary` から借りたものでも）を走らせ、`Summary.total(x)` がディスパッチする形です。
- **Kernel。** すべての型は `Kernel` を include します。`Kernel.to_s(x)` と `Kernel.inspect(x)` は型自身の `to_s` / `inspect` にディスパッチし、無ければ組み込みの形を使います。`"#{x}"`、`puts`、`p` はその略記です。

**必須の関数。** 本体が `raise NotImplementedError` だけ（メッセージの有無は問わない）の module 関数は必須です。module を include する各型がそれを定義し、`M.f(x)` はその定義にディスパッチします。ブロックを取るかは型側の定義から決まります。定義せずに include した型は、呼び出しが届きうる場所で `type` の問題になり、実行時は `NotImplementedError` です。`NotImplementedError` はプログラムの誤りで rescue できません（`raise T` と例外型だけ書くと、型名がメッセージになります）。

## 型を列挙する: `(A|B).f(x)`

`(A|B).f(x, args...)` は、`x` が取りうる型を操作自身に列挙します。実行時は `x` の型が `A.f` か `B.f` を選び、それ以外の型は `TypeError` です。実行前には、列挙した型のすべてが `f` を持つこと（持たなければ静的エラー）と、列挙にない型の値が来ないことが検査されます。結果は結果の和です。

```ruby
def weight(t) = (Leaf|Node).weight(t)   # 2 つの Struct 型の同名のフィールド
def size_of(x) = (String|Array|Hash).size(x)
```

- 列挙できるのは型です。組み込み型（`IO` も）と Struct 型を、それぞれ 1 度まで。`nil` は列挙できません。先に nil を検査します。
- 列挙した関数の形は違っていてよく、ユーザ関数の `*rest` はその分岐のために詰められます（`(IO|StringIO).print(io, a, b)`）。キーワードを取る関数は列挙できません。`case` で型を見分けてください。
- module のディスパッチと違い、宣言は要りません。呼び出しの場が集合を述べ、module を共有しない型（組み込み型、同名のフィールド）にも使えます。

## 引数の数とブロック

次は静的に検査されます。

- 引数の数（ユーザ関数も組み込みの操作も）。
- ユーザ関数には、関数が `yield` を含む（または `&b` を取る）とき**に限り**ブロックを渡す。ただし `block_given?` を検査する関数はブロック無しで呼べる。
- 組み込みの操作はブロックを必須とするか拒否する。

**スプラット引数。** `*xs` は Tuple か Array を展開します（他は `TypeError`）が、rest 引数にしか入りません。組み込みのもの（`puts(*lines)`、`format(fmt, *row)`、`Array[*xs, 0]`、`Set[*xs]`、`Array.push(a, *xs)`）か、ユーザ関数の `*rest`（`join(*parts)`）です。その前の引数は書き切るので、数は検査されます。`*rest` の無い関数へのスプラット、必須か省略可能な引数を埋めるスプラットは静的エラーです。`Array.zip`/`Range.zip`（Tuple の長さが引数の数）と `Hash[...]` へのスプラットも同様です。型推論では、Tuple は位置ごとに展開され、Array は要素型の任意個の引数を表します。
