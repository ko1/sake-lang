Sake-lang

the Sake language, pronounced /seɪk/

Sake is designed for the sake of finding a new place for types. It keeps Ruby's syntax, but you write the type on each operation, never on a variable. Each line then says exactly which function runs, and every name is checked before the program starts.

Ruby
name.upcase
3.times { p it }
pt.x
Sake
String.upcase(name)
Integer.times(3) { p it }
Point.get_x(pt)
  • Parsed by Prism
  • No types on variables, parameters, or fields
  • All names checked before running
  • Every operation checks its arguments

Tour

The idea

Most languages put types where a value is bound (variables, parameters, fields), and each use has to look back at that declaration. Sake puts the type where the value is used.

Types on bindingsTypes on operations (Sake)
Examplex: String; x.upcaseString.upcase(x)
Meaning of a lineNeeds the declarationFixed by the line itself
A misspelled operationFound once the receiver's type is knownFound by name, before running
CostThe type is written onceThe type is written at every use; the uses check each other

The examples on this page are real. Each one is a file in docs/examples/, and the dark panel under it is that file's actual output.

Running a program

CommandWhat it does
bin/sake FILE.sakeChecks the whole program, then runs it
bin/sake -c FILE.sakeOnly checks; does not run
bin/sake --strict FILE.sakeChecks more before running (level 2, below)
bin/sake --types FILE.sakeExperimental: prints the inferred types without running

How strict

LevelHow to askAlso stops before running
0--strict=0only syntax, names, argument counts, calls on values, and the like
1(the default)type: a value whose type (other than nil) does not fit the operation; rescue: a rescue of an exception never raised
2--strictnil: a value that may be nil, used without a check
3--strict=3index-nil: the result of x[k], used without a check; exhaustive: a case whose literal branches may miss some value
4--strict=4unrescued: a raise that may reach the top level

Items can also be named: --strict=type,nil, or --strict=3,-index-nil. Whatever is not checked before running is still checked while running, by each operation.

To try Sake in a browser, with completion and the inferred types on hover, build the playground in ide/ (see its README).

The exit status is 0 on success, 1 for an error while running, and 2 for an error found before running (nothing ran).

Operations carry their type

Type.op(subject, args…) calls the operation op of Type. The subject comes first. A call on a value, such as name.upcase, is rejected, and the error shows how to write it with the type. Chains are rewritten as a whole.

Every type and operation name is checked before the program starts, so a typo never fails halfway through a run:

Nested calls read inside out. Two forms let them read in order, with every step still naming its type: x.T.f(…) is T.f(x, …), and _ is the value of the previous statement.

Rules

  • Built-in names follow Ruby's core library: Integer.to_s, String.include?, Array.each. Names from other languages, such as Integer.to_string, do not exist.
  • Calls on values are always rejected, including on literals such as 3.times and "a".upcase. For a literal, the hint names its type.
  • p.x suggests Point.get_x(p), p.x = v suggests Point.set_x(p, v), and x.nil? suggests x == nil.

Numbers and operators

Operators behave as in Ruby: a + b runs the + of a's type. For the built-in types, a fixed table gives the result for each pair of operand types.

A pair marked — is reported before running. There is no implicit conversion. Every operation also checks its arguments while running; with --strict=0, the same mistake stops when it runs:

Writing the operator with a type, as in Integer.+(a, b), runs Integer's + directly: the left operand must be an Integer, and the right one any type that + takes with it:

== compares any two values: by content for Tuples, Arrays, Hashes, Sets, Records and Structs, and false between different types. Tuples and Arrays are ordered element by element, so a Tuple makes a sort key of several parts. -x runs the -@ of x's type, and !x is x ? false : true:

Rules

  • - * / % ** take the same numeric pairs as + (Integer, Float, Rational, Complex). * also takes (String, Integer); Arrays have + - * as in Ruby.
  • < <= > >= compare two numbers, two Strings, two Symbols, or two Tuples or Arrays element by element.
  • == != compare any two values. A Struct type with Comparable and <=> is equal where <=> gives 0.
  • Integer / and % follow Ruby: -7 / 2 == -4. Dividing an Integer by zero raises ZeroDivisionError.
  • Integer ** negative raises ArgumentError; for a Rational, write 2r ** -1.
  • x += 1 means x = x + 1. && and || short-circuit as in Ruby.

Functions

Functions have no type annotations, and do not need them: what a function accepts follows from its operations (String.upcase(s) needs a String), and each call is checked with the types it is given. A function works with any type its operations accept, so square below works on both Integer and Float.

Rules

  • The forms are def f(a, b) … end and def f(x) = expr.
  • Only required positional parameters are allowed. Default values, keyword arguments, rest parameters, and &blk are not.
  • first, *rest = xs and |a, *rest| collect the rest in an Array. *xs in arguments spreads only into built-ins that take any number of them: puts(*lines), format(fmt, *row), Array[*xs, 0].
  • return a, b and the literal [a, b] both make a Tuple. x, y = t takes it apart, and an Array too: missing elements are nil, extra ones dropped, as in Ruby.
  • Definitions are collected before anything runs, so a function may be called above its definition.
  • Recursion is limited to a depth of 10,000. Deeper calls raise SystemStackError.

Control flow

if/elsif/else, unless, while, until, the modifier forms, and c ? a : b all work as in Ruby.

Matching by type

x in Integer tests a value's type. case x with in branches picks the branch by type, literal, or Record shape. Inside a matching branch, the variable has the matching type, so a value that may be an Integer or a String can be used without a type report. There is no ===, so case/when is not supported.

The set of types is closed, so a case that may match nothing is found before running:

Rules

  • Only nil and false are falsy. 0 and "" are truthy.
  • An if without an else, and every loop, gives nil.
  • break and next work inside while and until.

Blocks

An operation that takes a block is called like any other, with the subject first. A block's single parameter can be named it or _1.

Your own functions receive a block through yield. If a block has several parameters and receives one Tuple, the Tuple is taken apart. return inside a block leaves the enclosing function.

Blocks are not values, so the interpreter knows which block each yield runs and checks block use before running:

break ends the call the block was given to, which then gives the break's value. A parameter can be taken apart, |(name, n), i|, and |head, *rest| collects the rest:

Rules

  • A user function takes a block if and only if its body contains yield. A built-in operation either requires a block or rejects one.
  • A block with no parameters ignores its arguments. Otherwise, the number of arguments must match. A block with several parameters takes one Tuple or Array apart.
  • next v gives the block's value; break v the value of the call it was given to.
  • A block can read and assign the variables around it.
  • proc, lambda, ->, and &blk are not available.

Struct types

Point = Struct.new(:x, :y) creates the type Point and its operations. Ruby's Data.define is not used, because Ruby's Data is immutable. Fields are mutable, and values are shared by reference.

OperationMeaning
Point.new(1, 2)Create a Point. Pass one positional argument per field.
Point.get_x(p)Read the field x
Point.set_x(p, v)Write the field x in place, and return v
Point[p1, p2]An Array of Point (see Tuples, Records, and arrays)

"#{expr}" interpolates as in Ruby. A type can define its own to_s (used by puts, print, "#{…}", Array.join, and format's %s) and inspect (used by p). Each must take the value and return a String.

Add your own operations inside class Point. Inside it, unqualified names such as get_x refer to Point's operations. def Point.f is shorthand for defining f inside class Point.

Inside a function of a Struct type, @x is shorthand for field x of the function's first argument, which is the subject by convention. @x reads the field, @x = v writes it, and @x += v updates it. The type comes from the enclosing class Point, so @x is still an operation with a type.

A type can also be declared with its settings after <. reader:, writer:, and accessor: choose which fields have get_ and set_ outside the class; default: gives default values, which also fix a field's type; exception: true makes an exception type.

Prefer this form, with reader: for every field that is not changed from outside: most fields are never changed after new, and with reader: every write to a field is in its own class, where the checker finds its type. List a field under accessor: only when code outside the class must change it. Struct.new(:x, :y) is shorthand for accessor: on every field.

Outside such a function there is no p.x. Field access is an operation with a type:

Where names resolve

A call without a type, f(x), is resolved before running. It searches these places in order, and the first match wins:

  1. the enclosing class or module
  2. top-level functions
  3. Kernel (puts, print, p)

The inner definition wins, so common names such as open stay usable. To reach an outer one, write its namespace, as in Kernel.puts(…).

Operators for your own types

An operator belongs to a module: Arithmetic (+ - * / % **), Comparable (<=> and < <= > >=), Bitwise, and Indexable ([], []=). A type joins by including the module and defining the operator. With Comparable, <=> alone gives the comparisons and makes Array.sort work.

Listing the types on the operation

When a value may be one of a few types that have an operation of the same name, list them on the operation: (A|B).f(x) runs the f of x's type. The list is checked before running:

Sharing functions with include

class adds operations to a type, and module is a namespace with no type. include M borrows M's functions, as Ruby's modules do, but statically. Inside a borrowed function, unqualified names are looked up in the namespace that includes it, so Summary can use the each that Basket or Countdown provides.

A module's functions are called in one of two ways. Functions after module_function are called directly (Units.km(x)). Calling any other function through its module (Summary.total(x)) dispatches to the function of x's type, which must include the module. Like Elixir's protocols, the module name on the call says that the function is picked while running.

A missing requirement is found before running. So are a class that is not a type, and a direct call to a function that needs its includer:

A module states what each includer must define with a function whose body is only raise NotImplementedError. A type that includes the module but lacks it is reported where the function is reached:

Rules

  • The includer's own definition wins over a borrowed one. Modules included by a module are borrowed too.
  • include is not inheritance: M.f(x) always runs M's own f. There is no class A < B; reuse a type by composition.

Tuples, Records, and arrays

A literal has no operation with a type, so its shape fixes its type when it is created. A growable collection is made by an operation with a type.

Written asIsElement types
[1, "a"]TupleFixed length and fixed positional types. Take it apart with x, y = t.
{x: 1, y: "a"}RecordThe set of fields and their types, for example {x: Integer, y: String}. Take it apart with r => {x:, y:}.
Array[1, "a"]ArrayNot declared. Any value can be added.
Float[], Point[p]Array of TT. Every write is checked.

A Record is read with a pattern. r => {mean:, count: n} binds mean and n. Field order does not matter, and a Record is never a Struct value, even when the fields match.

In Sake, [] and {} are not growable collections. Ruby code that grows them stops with a hint:

Indexing

x[k] runs the [] of x's type, and x[k] = v its []=. Array, Hash, String, Tuple, and MatchData have them.

  • A miss gives nil, as in Ruby, so with --strict you check a[i] before using it. Array.fetch raises an error instead.
  • A Tuple's length is part of its type, so reading outside it is an error.
  • Writing a Tuple position needs a value of that position's type.

Point[1, 2] means "an Array of Point". It is not Ruby's shorthand for Point.new(1, 2). When the mistake is visible in the source, it is reported before running:

More on Arrays: Array.new(n, v) and Array.new(n) { |i| … }, + - *, element assignment as a multiple-assignment target (a swap), two indexes s[start, length], and a start value for sum, which an empty Array gives instead of the Integer 0:

Tuples tagged by a Symbol

An Array of Tuples whose first element is a Symbol tag keeps each kind apart. Testing the tag, after |kind, arg| takes a Tuple apart (or with case t[0]), tells the type of the rest:

Rules

  • An Array of T checks each element on creation and on push, append, and concat. There is no conversion, so an Integer cannot go into Float[].
  • map, select, sort, and similar operations return an Array with no declared element type.
  • The contents of a Tuple or Record may be replaced by values of the same type. A Tuple is written with t[i] = v; a Record has no write syntax yet. The length is part of the type.

Where a type is worth writing

A function needs no type: its operations say what it accepts. A Struct's field needs none either: its type comes from the values written to it, which T.new and T.set_x show. The one place a type pays is an Array that is filled later. Made with Array[], its element type is whatever gets pushed, so a wrong value is reported where the elements are used, far from where it went in:

Made with its element type, Integer[] (or Float[], Point[], Tuple[]), every push is checked where it happens. The type is written on the operation that makes the Array, not on a variable:

Hash, Set, Range, Regexp

Hash, Set, Symbol, Range, and Regexp work as in Ruby. Their operations carry the type like everything else (Hash.each, Range.to_a, String.match), while h[k], 1..5, :name, and /re/ are written as in Ruby.

  • Hash[k => v] and Hash.new(0) make a Hash, because {…} is a Record.
  • A missing key gives nil, or the default given to Hash.new.
  • A block over a Hash receives [key, value], which |k, v| takes apart.

Rules

  • Hash keys and Set elements compare as == does: numbers, Strings, Symbols, true, false, nil, Time, and Tuples, Records, Arrays, Hashes, Sets and Struct values made of these. A Struct type that defines its own == (or <=> with Comparable) cannot be a key. A Tuple or Record key is copied when stored.
  • There are no globals such as $1. Keep the MatchData: m = String.match(s, re), then m[1].
  • Hash.new { … } is not available, because blocks are not values.
  • a[1..2] and s[1..3] slice an Array or a String.

nil

A value that may be absent is simply nil: its type is nil | T, with no Option wrapper. Check it with if x, while x, x != nil, or return unless x. When a nil reaches an operation that needs something else, the error tells you where it can come from.

By default (level 1), an unchecked nil is caught when it runs. --strict (level 2) reports every unchecked use before running. A local variable you have tested counts as checked. A field you read again does not, because fields are mutable.

You writeThe local x is known to be
if x, while x, x && …not nil, where x was truthy
x != nil, x == nilnot nil, or nil, in the matching branch
return unless x, next if x == nilnot nil after that line

Exceptions

raise, rescue, else, ensure, and retry work as in Ruby. An exception type is declared with Exception.new: it is a Struct type whose first field is message. There is no hierarchy, so a rescue lists the types it catches.

The checker tracks which exceptions each function may raise. By default it reports a rescue that can never match; level 4 also reports a raise that nothing rescues:

Rules

  • raise "msg" raises RuntimeError. raise T, "msg" works when T has only message; otherwise write raise T.new(…).
  • rescue => e catches everything rescuable; e is a union, so narrow it with case e in …. Exception.message(e) reads any exception's message.
  • TypeError, NoMatchingPatternError, and SystemStackError are program errors: they cannot be rescued.

What Sake rejects

Sake rejects anything that would hide which code runs, and anything not designed yet. All of it is reported together, before running:

Rules

  • Never allowed: self, @x outside a function of a Struct type, send, method_missing, define_method, the eval family, instance_variable_get/set, const_get/set, and class inheritance.
  • By design: there are no value constants. Define a function instead: def pi = 3.14159, then call pi.

Seeing the types

--types runs a whole-program type inference without running the program. For every operation that checks its argument, it reports one of the following:

  • proven: the check always passes;
  • partial: the value's type is a union, so the check is still needed;
  • error: the check always fails;
  • unknown: the inference could not tell.

It also lists the element type of each Array and the type of each field. None of these types were written in the program. The playground (ide/) shows the same results in its Types tab and on hover.

Errors

Before running (exit status 2)

All errors are reported at once, in source order, and nothing runs.

FILE:LINE:COLUMN: error: MESSAGE
  hint: SUGGESTION

Errors found before running:

  • syntax errors;
  • unknown types, operations, and functions;
  • a wrong number of arguments;
  • a block given where none is taken, or missing where one is required;
  • calls on values;
  • forbidden or unsupported syntax;
  • duplicate definitions;
  • a literal of the wrong type in T[…];
  • by default (level 1), a value whose type does not fit the operation, such as "" + 1;
  • with --strict (level 2), a value that may be nil used without a check;
  • with --strict=3, the result of x[k] used without a check, and a case whose literal branches may miss a value.

Not yet supported

Each of these is rejected before running. Most are waiting on a design decision.

  • Writing to Record fields
  • The type scope Integer.(a + b)
  • case/when (use case/in), %w[], %i[]
  • for: not planned; iterate with an operation such as Range.each(1..3) { |i| … }
  • Patterns other than types, literals, alternatives, and Record shapes (array and find patterns, pins, guards)
  • Built-in constants such as Math::PI and Float::INFINITY
  • Blocks as values
  • Several files (require)
